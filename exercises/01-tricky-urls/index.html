تمرین ۱: کدام URL شما را فریب می‌دهد؟

مهلت تحویل: چهارشنبه ۲۹ مهر ۱۴۰۵، ساعت ۲۳:۵۹
نمره: ۱۰ · ارزیابی خودکار

مسئله

فرض کنید در پنل داخلی دانشگاه، کارمندها لینک وارد می‌کنند و سرور برای هر لینک یک پیش‌نمایش می‌سازد؛ یعنی خودش آن صفحه را باز می‌کند و می‌خواند. برای امنیت، سرور فقط اجازه دارد سایت خود دانشگاه را باز کند. در این تمرین نشانی سایت دانشگاه را scu.test می‌گیریم. این دامنه آزمایشی است و در اینترنت وجود ندارد.

همکارتان برای اینکه جلوی لینک‌های دیگر را بگیرد، این تابع را نوشته است:

export function guard(input) {
  if (!input.includes('scu.test')) return { ok: false }
  return { ok: true, url: input }
}

ایراد کار اینجاست: اینکه scu.test جایی در متن یک URL آمده باشد، به این معنا نیست که آن URL واقعاً به همین سایت می‌رود. در این تمرین:

  • هشت URL را امتحان می‌کنید که این تابع را فریب می‌دهند.
  • تابع را درست می‌کنید.
  • به سه سؤال دربارهٔ همان هشت URL جواب می‌دهید.

پیش از شروع

این اولین تمرین درس است. اگر هنوز راهنمای تمرین‌ها را نخوانده‌اید، اول آن را بخوانید: ساختن مخزن تحویل، روش تحویل، نمره و تأخیر همان‌جا آمده است.

از اینجا به بعد همهٔ دستورها را داخل همین پوشهٔ ex01 بزنید. چهار فایل در آن هست:

۲. ببینید با هر URL چه می‌شود

هشت URL تمرین در urls.txt هستند. شمارهٔ هر کدام همان شمارهٔ خطش است:

1  http://scu.test@evil.test/login
2  http://evil.test\@scu.test/
3  http://SCU.test:80/a/./b/../c
4  http://scu.test./
5  http://scu.test:0080/
6  http://[0:0::1]:8080/x
7  http://2130706433/scu.test
8  http://scu.test/%2e%2e/admin

اول کمی فکر کنید. پیش از اینکه چیزی را اجرا کنید، به شمارهٔ ۲ نگاه کنید: به نظرتان مرورگر با این URL به کدام host وصل می‌شود؟ curl هم به همان‌جا می‌رود؟ لازم نیست جوابتان را جایی بنویسید یا تحویل بدهید. فقط در ذهنتان نگهش دارید تا بعد ببینید درست فکر کرده بودید یا نه.

حالا اجرا کنید:

node observe.mjs

این دستور هر URL را دو بار می‌خواند: یک بار همان‌طور که مرورگر می‌خواند، و یک بار با curl. چیزی به اینترنت فرستاده نمی‌شود، پس لازم نیست URLها را خودتان جایی باز کنید. دو فایل ساخته می‌شود:

  • فایل observed.json که نتیجه را برای هر هشت URL دارد.
  • فایل evidence/curl.txt که خروجی کامل curl است.

فایل observed.json را باز کنید. برای هر URL این‌ها را می‌بینید:

مقدار یعنی چه
includes تابع همکارتان این URL را قبول می‌کند (true) یا رد می‌کند (false)
browser.host و browser.path و browser.origin مرورگر این URL را چطور می‌فهمد
curl.host و curl.target آنچه curl واقعاً فرستاد: مقدار Host و مسیر درخواست

۳. تابع guard را درست کنید

فایل guard.mjs را باز کنید و تابع را عوض کنید. به اسم فایل، اسم تابع و کلمهٔ export دست نزنید. تابع یک رشته می‌گیرد و یکی از این دو را برمی‌گرداند. اولی یعنی «این URL مجاز است» و دومی یعنی «مجاز نیست»:

{ ok: true, url: '...' }
{ ok: false }

تابع شما باید این پنج کار را بکند:

  1. اگر ورودی اصلاً URL نبود، ردش کند. در این حالت هم نباید خطا بدهد.
  2. فقط http و https را قبول کند.
  3. فقط وقتی قبول کند که origin دقیقاً http://scu.test یا https://scu.test باشد.
  4. اگر URL نام کاربری یا رمز داشت، ردش کند.
  5. وقتی قبول می‌کند، در url همان href را برگرداند که new URL(input) می‌دهد، نه متنی که به تابع داده شده.

دو مثال:

guard('http://SCU.test:80/a/./b/../c')
// { ok: true, url: 'http://scu.test/a/c' }

guard('http://scu.test@evil.test/login')
// { ok: false }

حواستان باشد که origin با کوچک‌ترین تفاوت عوض می‌شود: پورت دیگر (مثل 8080)، زیردامنه (مثل sub.scu.test) و حتی یک نقطه در آخر (scu.test.). همهٔ این‌ها باید رد شوند.

۴. به سه سؤال جواب بدهید

جواب‌ها را در answers.json بنویسید. جواب هر سؤال فهرستی از شمارهٔ URLهاست و هر سؤال دست‌کم یک جواب دارد. شکل فایل این است (این عددها فقط مثال‌اند):

{
  "other_origin": [1, 5],
  "wrongly_blocked": [8],
  "parsers_differ": [6]
}
کلید سؤال جوابش کجاست
other_origin تابع همکارتان کدام URLها را قبول می‌کند، در حالی که origin آن‌ها http://scu.test نیست؟ آن‌هایی که includes برابر true است ولی browser.origin چیز دیگری است
wrongly_blocked تابع همکارتان کدام URLها را رد می‌کند، در حالی که origin آن‌ها http://scu.test است؟ آن‌هایی که includes برابر false است ولی browser.origin همین است
parsers_differ مرورگر و curl سر کدام URLها با هم فرق دارند؟ آن‌هایی که browser.host با curl.host یکی نیست، یا browser.path با curl.target

در سؤال سوم بزرگ و کوچک بودن حروف مهم نیست. جوابش به نسخهٔ curl شما بستگی دارد، پس همان چیزی را بنویسید که در observed.json خودتان می‌بینید.

۵. تست کنید و تحویل بدهید

  1. تست را اجرا کنید:

    node ../../ie-course-scu/exercises/01-tricky-urls/check/check.mjs .

  2. سه خط می‌بینید. اگر خطی با ✗ شروع شد، یعنی آن قسمت هنوز ایراد دارد. درستش کنید و دوباره تست را اجرا کنید تا هر سه خط ✓ شود.

  3. اگر از هوش مصنوعی کمک گرفتید، در فایل AI.md بنویسید از چه ابزاری و برای چه کاری.

  4. همه‌چیز را commit و push کنید:

    git add .
git commit -m "ex01"
git push origin main

  5. صفحهٔ مخزنتان را در GitHub باز کنید و مطمئن شوید پوشهٔ ex01 این فایل‌ها را دارد: guard.mjs و answers.json و observed.json و evidence/curl.txt.

این تست فقط دو چیز را نگاه می‌کند: اینکه فایل‌ها سر جایشان باشند، و اینکه guard با هشت URL تمرین درست کار کند. درست بودن جواب سه سؤال و رفتار guard با URLهای پنهان بعد از مهلت بررسی می‌شود.

اگر خواستید بیشتر بدانید

این دو مورد نمره ندارند.

  • نشانی http://scu.test\@evil.test/ را در فایلی به اسم my.txt بگذارید و node observe.mjs my.txt را اجرا کنید. مرورگر و curl آن را به دو host متفاوت می‌برند. برای همین است که guard باید href را برگرداند، نه متن ورودی را.
  • نشانی شمارهٔ ۷ به 127.0.0.1 می‌رسد، یعنی به خود سرور. فکر کنید کسی با این راه به چه چیزهایی دست پیدا می‌کند، و دربارهٔ آسیب‌پذیری SSRF بخوانید.

پل به بخش بعد

فایل evidence/curl.txt را باز کنید و خط Host را پیدا کنید. curl نام سایت را یک بار دیگر، داخل خود درخواست، فرستاده است. سرور که پیدا شده بود؛ پس چرا باید نام خودش را دوباره بشنود؟ بخش بعد از همین سؤال شروع می‌شود.
